# 破晓 (PoXiao) — 需求清单

> 基于 RayScan 扫描 50 个补天公益厂商的实战教训整理
> 2026-05-25

---

## 核心理念

```
RayScan 的教训: payload 盲打在真实生产站上 ≈ 0 漏洞
破晓的方向:     信息收集 → 技术栈识别 → 已知漏洞匹配 → 精准打击
```

**破晓不是 RayScan 的升级版，是换一套检测哲学。**

---

## 一、架构需求

### 1.1 渐进式输出（最高优先级）

| 问题来源 | RayScan batch 要等全部跑完才出结果 |
|----------|--------------------------------------|
| 要求 | 扫完一个目标立即输出报告，不等不靠 |
| 实现 | 每个目标独立扫描 → 独立报告文件 → 实时通知 |
| 验收 | 50 个目标扫完第 1 个就能看到第 1 份报告 |

### 1.2 目标存活检测

| 问题来源 | 50 个目标中有不可达域名（guilinbank.com.cn 等），照扫不误浪费时间 |
|----------|----------------------------------------------------------------|
| 要求 | 扫描前先做存活检测（HTTP HEAD / TCP 连接），不可达的直接跳过并记录 |
| 实现 | 并发检测，超时 5s，结果分级：可达 / 跳转 / 不可达 |
| 验收 | 不可达目标不进入扫描队列，日志中标记原因 |

### 1.3 断点续扫

| 问题来源 | 全量扫描跑 2 小时被杀掉，进度全丢 |
|----------|------------------------------------|
| 要求 | 中断后可从上次进度恢复 |
| 实现 | 每个目标扫完后标记完成状态，存在 checkpoint 文件 |
| 验收 | Ctrl+C 后重新运行，跳过已扫目标 |

### 1.4 并发控制

| 问题来源 | RayScan batch 用 asyncio.gather 简单并发，无动态调整 |
|----------|------------------------------------------------------|
| 要求 | 可配置并发数，支持速率限制（避免被 WAF 封） |
| 实现 | 信号量 + 令牌桶，每个目标独立限速 |
| 验收 | 并发 5 时不会对单目标发起超过 10 req/s |

## 二、目标管理

### 2.1 多源输入

| 要求 | 支持从以下来源加载目标 |
|------|------------------------|
| 实现 | 文本文件（每行一个 URL）/ 命令行参数 / 粘贴板 |
| 格式 | `http://example.com` / `https://example.com/path` / `example.com`（自动补全） |
| 去重 | 自动去重，同一域名不同路径视为同一目标 |

### 2.2 域名发现

| 要求 | 给定公司名称，自动查找其官方域名 |
|------|-----------------------------------|
| 场景 | 补天 3900 家厂商列表 → 批量解析域名 |
| 实现 | 搜索 API / 百度 / ICP 备案查询 / 常见域名模式匹配 |
| 验收 | 准确率 > 60%（不需要 100%，遗漏的可手动补充） |

### 2.3 目标分类

| 要求 | 自动识别目标类型 |
|------|------------------|
| 分类 | 政府 `.gov.cn` / 教育 `.edu.cn` / 银行 / 保险 / 电商 / 通用企业 |
| 用途 | 不同类型使用不同的检测策略和 payload 集 |

## 三、信息收集（破晓的核心竞争力）

### 3.1 技术栈识别

| 要求 | 扫描前先识别目标使用的技术 |
|------|---------------------------|
| 识别项 | Web 服务器（Nginx/Apache/IIS/Tomcat） / 后端语言（PHP/Java/Python/ASP.NET/Node.js） / CMS（WordPress/DedeCMS/ThinkPHP/Discuz!） / CDN/WAF |
| 来源 | HTTP 响应头 / HTML meta / URL 特征 / Cookie / 错误页面 |
| 用途 | 不同技术栈使用不同的检测策略 |

### 3.2 敏感路径/文件发现

| 要求 | 发现目标上的敏感文件和路径 |
|------|--------------------------|
| 核心 | `robots.txt` / `sitemap.xml` / `.git/config` / `.env` / `phpinfo.php` / 后台登录页 / API 文档 |
| 来源 | 通用路径字典 + 技术栈特定路径（如 ThinkPHP 的 `runtime/`） |
| 验收 | 每次扫描至少发现 1 个路径/文件线索 |

### 3.3 JS 端点提取

| 要求 | 从 JS 文件中提取 API 端点、密钥、敏感信息 |
|------|------------------------------------------|
| 实现 | 下载页面 JS → 正则提取 endpoint / API key / token / 内网 IP |
| 来源 | 内联 JS + 外部 JS 文件 |
| 注意 | 不把路径发现算成"漏洞"——这是 RayScan 的错误做法 |

### 3.4 子域名收集（可选）

| 要求 | 发现目标的子域名 |
|------|------------------|
| 来源 | 证书透明度日志 / DNS 枚举 / 搜索引擎 |
| 优先级 | 低，可作为后续版本功能 |

## 四、漏洞检测

### 4.1 检测哲学

```
不做:
  ✗ 对每个参数发射 1000 个 SQLi payload（浪费时间，容易被封）
  ✗ 把路径发现算成漏洞（RayScan 的 JSPathFinder 1039 个全是噪音）
  ✗ 检测理论存在但实际无法利用的漏洞

要做:
  ✓ 发现技术栈 → 匹配已知 CVE/公开漏洞
  ✓ 检测敏感信息泄露（.git/config.bak/phpinfo）
  ✓ 检测配置不当（CORS/未鉴权的 API/目录穿越）
  ✓ 检测已知 CMS/框架版本的公开漏洞
```

### 4.2 模块列表（v1.0）

| 模块 | 说明 | 优先级 |
|------|------|--------|
| `info_leak` | 敏感信息泄露（备份文件、配置文件、源码泄露） | P0 |
| `tech_stack` | 技术栈识别 + 版本号提取 | P0 |
| `cve_match` | 已知 CVE/公开漏洞匹配（基于技术栈+版本） | P1 |
| `api_detect` | API 端点发现 + 鉴权检测 | P1 |
| `cors_misconfig` | CORS 配置不当检测 | P1 |
| `dir_traversal` | 目录穿越（精准 payload，不盲打） | P2 |
| `cmd_inject` | 命令注入（基于已知漏洞点） | P2 |
| `sqli_check` | SQL 注入（仅检测明显特征，不穷举） | P3 |

### 4.3 不做的检测

| 模块 | 原因 |
|------|------|
| XSS 盲打 | 生产站 XSS 需要手动验证，自动化漏报率高 |
| SSRF 盲打 | 需要 OOB 服务器，增加复杂度 |
| XXE 盲打 | 同上 |
| 暴力破解 | 容易被封，效率低 |
| 0day 挖掘 | 不在自动扫描范围内 |

## 五、报告系统

### 5.1 报告格式

| 格式 | 用途 |
|------|------|
| JSON | 机器可读，供后续处理 |
| Markdown | 人工阅读 + 可提交到 SRC |
| HTML | 可视化展示（可选） |

### 5.2 SRC 报告生成

| 要求 | 一键生成符合补天/漏洞盒子格式的报告 |
|------|--------------------------------------|
| 内容 | 漏洞名称 / 漏洞等级 / 漏洞URL / 漏洞描述 / 复现步骤 / 修复建议 |
| 验收 | 生成后可直接复制粘贴提交到补天 SRC |

### 5.3 结果分级

| 等级 | 定义 |
|------|------|
| P0-Critical | 可直接导致服务器失陷（RCE/命令注入/未授权访问） |
| P1-High | 可获取敏感信息或造成损失（SQLi/敏感文件泄露） |
| P2-Medium | 信息泄露或配置问题（CORS/目录穿越/版本泄露） |
| P3-Low | 低风险（Server 版本/非敏感信息） |
| Info | 仅做记录（技术栈信息/端点发现） |

## 六、从 RayScan 迁移的教训清单

| # | 教训 | 影响 |
|---|------|------|
| 1 | **payload 盲打在真实站点无效** | 破晓放弃"发射 payload 看反射"模式 |
| 2 | **batch 不渐进输出 = 等于没扫** | 破晓强制渐进输出 |
| 3 | **js_analysis 崩溃的模块不如关掉** | 破晓的每个模块必须稳定运行 |
| 4 | **JSPathFinder 1039 个"漏洞"全是噪音** | 破晓严格区分"漏洞"和"信息" |
| 5 | **50 个目标 44 分钟=0 漏洞** | 与其扫 50 个不如深挖 5 个 |
| 6 | **不可达目标浪费时间** | 破晓先存活检测 |
| 7 | **没有断点续扫** | 破晓每个目标完成后记 checkpoint |
| 8 | **WAF 检测与绕过对挖洞帮助有限** | 破晓不做 WAF 绕过 |
| 9 | **中文编码/GBK 兼容要支持** | 破晓原生支持中文路径 |
| 10 | **补天厂商列表的域名发现是硬需求** | 破晓要有域名自动发现功能 |
