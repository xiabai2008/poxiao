## 2. 环境与资源清单

### 2.1 环境矩阵

> 模板硬指标要求环境矩阵含 **dev / int / uat / prod** 四类。本项目为本地 CLI（X3 冻结无云），此四类**非独立云集群**，而是**交付生命周期阶段 + 单机运行视图**：dev/int 在维护者本机与 CI Runner 上完成开发与联调；uat 为 release candidate 在用户本机试跑验收；prod 为正式版在用户本机运行。该视图与《系统设计》§5.1 冻结的「dev / local / prod 三类」一致——系统设计之「local」即本表 uat + prod 合并视图（用户本机同时承载验收与生产运行，无云端隔离）。

| 环境 | 用途 | 集群隔离 | 数据 | 网络访问 |
| --- | --- | --- | --- | --- |
| dev | 开发自测（维护者本机 / CI） | 共享（开发机 / CI Runner，无独立集群） | 模拟数据（targets_test 等） | 内网 / 本机 |
| int | 联调（CI 合并后集成测试） | 共享（CI Runner） | 模拟数据 | 内网 |
| uat | 预发 / 验收（release candidate，用户本机试跑） | 单机（用户本机，独立于 prod 数据） | 仿生产（真实目标样本，非提交数据） | 本机 + 出站 E-xx 白名单 |
| prod | 生产（用户本机 pip 安装正式版） | 单机（用户机器） | 真实数据（真实扫描目标 / 报告，数据不出本机） | 本机 + 出站 E-xx 白名单 |

**填写要求**：四类环境均**非独立云集群**（X3 冻结）；隔离策略 = 用户本机 / CI Runner 进程级隔离，无 VPC / 无跨账号。

| 层次 | 主要组件 |
| --- | --- |

#### 3.1.2 拓扑要素清单

- **跨 Region 部署**：否（本地单机，数据不出本机，D5§4.2）

- **流量入口路径**：用户终端 → CLI（无公网入口）；GuanXing 为 127.0.0.1 本地回环（仅本机，不暴露公网）

- **数据库访问路径**：本地 sqlite3 文件（WAL），进程内直连，无 Proxy / 无远程

### 3.3 高可用与故障容错

#### 3.3.1 故障域划分

> 模板原「单 Pod / 单 Node / 单 AZ / 单 Region」四层针对云部署。本项目为本地单机，按本地 CLI 现实映射为**四层故障域**：单进程（≈单 Pod）、单目标、单机（≈单 Node/AZ 合并，无云 AZ）、跨机器（≈单 Region，无多 Region）。

| 故障域 | 影响范围 | 容错机制 | 预期 RTO |
| --- | --- | --- | --- |
| 单命令 / 进程 | 当前扫描任务（单进程） | Ctrl+C 安全退出 + checkpoint（F7） | ≤ 1min 重跑 |
| 单目标 | 该目标 | 跳过 + 记录（QS-03） | 瞬时无影响 |
| 单机（本机） | 全部本地任务 | 复制 db + 重跑（§4.3.2） | ≤ 30min |
| 跨机器（多用户独立部署） | 仅该用户本机 | 各用户本机独立，互不影响；无共享依赖 | 各自恢复 ≤ 30min |

> **可用性来源拆分**：本机环境（用户机器 OS / Python 运行时）= 用户保障；本系统自身保障（单目标失败不中断整批 BD-03/QS-03、续扫 F7、降级 BD-01/02）= 研发团队；强依赖外部 E-xx 故障策略（降级 / 跳过 / 限流退避）= 研发团队。

#### 3.3.2 负载均衡

| 维度 | 取值 |
| --- | --- |
| 类型 | 不适用（本地单进程 CLI，无 LB） |
| 健康检查 | 进程级：命令可正常执行；`POXIAO_DEBUG` 控制堆栈 |
| 会话保持 | 不适用 |

#### 3.3.3 健康检查配置

| 维度 | 取值 |
| --- | --- |
| 检查方式 | 进程级：命令启动即执行（`poxiao --version` / `poxiao scan targets_test.txt` 可跑通） |

| 失败阈值 | 启动即崩溃（ImportError / ConfigError）→ 触发 AL-01（§5.3） |
| 连续成功阈值 | 不适用（无持续探活） |

#### 3.3.5 容灾切换配置

| --- | --- |
| 单 AZ / 多 AZ | 无多 AZ（本地单机） |

> 本地 CLI 的「部署」= 构建 wheel + 发布 PyPI / git tag；「部署到 dev/int」= CI 安装测试。八阶段对齐模板：

| 阶段 | 触发条件 | 关键动作 | 失败处理 |
| --- | --- | --- | --- |
| 1 构建 | 推送 / PR | 拉代码 → `pip build` wheel → 单元测试（pytest+pytest-asyncio）→ 构建产物 | 阻断后续阶段 |
| 2 代码扫描 | 构建后 | 静态扫描（ruff / flake8）/ 类型（mypy 可选）/ 复杂度 | 不达标阻断 |
| 3 安全扫描 | 构建后 | SCA（pip-audit 依赖漏洞）/ 密钥扫描（gitleaks，防 API Key 入仓） | 高危阻断 |
| 4 集成测试 | 合并到 develop | 集成测试 / 契约测试（CLI 子命令）/ 模板加载校验（215） | 阻断后续阶段 |
| 5 制品打包构建 | 构建/测试通过 | 构建 wheel（`poxiao-{ver}-py3-none-any.whl`）；推 PyPI 或内部 index；打 tag | 失败重试 |
| 6 部署集成环境 | Package 完成 | 自动 `pip install` 到 CI Runner（dev/int）跑冒烟 | 失败回滚到上一版本 |
| 7 部署测试环境 | 手动触发（release candidate tag） | 安装到 uat 试跑（真实目标样本）→ 冒烟 | 失败回滚到上一 tag |
| 8 部署生产环境 | 人工审批（维护者） | 正式 tag → PyPI 发布 → 用户 `pip install -U poxiao` | 按回滚策略（§6.1）实施回滚 |

## 6. 应急与回滚

### 6.1 回滚机制

#### 6.1.1 回滚触发条件

- 生产错误率：命令无法启动 / 整批 0 结果且无报告（AL-01 / AL-02）
- P90 耗时：单批 P95 > 10s 持续退化（性能基线）
- 关键告警触发：AL-03 外部 API 大面积降级

#### 6.1.2 回滚决策人

- 维护者（On-call 主值班）可独立决定 P0 回滚到上一版本（`pip install poxiao==上一稳定版`）
- 其他级别由 Owner（维护者）决定

#### 6.1.3 回滚执行 SOP

| 对象 | 回滚方式 | 预计耗时 | 有损风险 / 数据丢失 |
| --- | --- | --- | --- |
| 应用版本 | `pip install poxiao==上一稳定版` | ≤ 5 min | 无（扫描可重跑） |
| 配置 | config.yaml 版本管理（git），回退上一版本 | ≤ 1 min | 无 |
| 数据库资源（SQLite） | DDL 变更必须可回滚（仅追加 / 兼容字段，禁止 DROP COLUMN 与代码同发布）；变更前文件复制备份（§4.3.2） | ≤ 30 min | 有（旧版本读取新字段需兼容，已约定向后兼容） |

> 注：GuanXing SQLite 为全新单文件（§4.5 数据迁移未启用），DDL 仅向后兼容追加；破坏性变更禁止与代码同发，须前置备份。

### 6.2 故障应急 Runbook

#### 6.2.1 Runbook 索引

| Runbook 编号 | 关联告警 | 故障场景 | Owner |
| --- | --- | --- | --- |
| RB-01 | AL-01 | 命令无法启动（ImportError / ConfigError） | @维护者 |
| RB-02 | AL-02 | 整批 0 报告产出 | @维护者 |
| RB-03 | AL-03 | 外部 API 大面积降级 | @维护者 |
| RB-04 | AL-04 | 单目标高失败率 | @维护者 |
| RB-05 | AL-05 | 磁盘水位 > 80% | @用户 |

#### 6.2.2 Runbook 编写规范

每条 Runbook 按以下结构编写：
- **症状**：触发该 Runbook 的可观测特征（大盘指标 / 告警内容 / 用户反馈）
- **诊断（按顺序执行）**：定位根因的诊断步骤，明确使用的可观测工具与查询路径
  1. 查终端报错 / 日志（`~/.poxiao/logs/` 或 `scan_results/` 摘要）
  2. 复现最小命令（`poxiao scan targets_test.txt`）
- **缓解**：分场景的处置动作（与回滚 §6.1、降级、限流、切换等机制衔接）
  - 场景 A → 回滚版本 / 修复 config
  - 场景 B → 降级跳过外部源（BD-01/02）
- **升级**：缓解未生效的升级条件、升级路径与对外通告机制

#### 6.2.3 RB-01：命令无法启动

- **症状**：`poxiao scan` 启动即报 ImportError / ConfigError / ModuleNotFound。
- **诊断（按顺序执行）**：
  1. 查终端堆栈（无 `POXIAO_DEBUG` 时加 `POXIAO_DEBUG=1` 复现）。
  2. 查 `~/.poxiao/config.yaml` 是否损坏（读取失败 fail-fast）。
  3. 查 `pip show poxiao` 版本与依赖是否完整。
- **缓解**：
  - 场景 A（依赖缺失）→ `pip install -e .` 重装。
  - 场景 B（config 损坏）→ 备份后 `poxiao config init` 重建 L2。
- **升级**：重装无效 → 回滚到上一 tag（§6.1.3），并提 GitHub issue（D4）。

#### 6.2.4 RB-02：整批 0 报告产出

- **症状**：扫描跑完但 `scan_results/` 无报告文件，AL-02 触发。
- **诊断**：
  1. 查目标存活（BD：不可达目标被跳过属正常）。
  2. 查模板加载（215 是否全部解析，BD-03 单模板异常应跳过而非中断）。
  3. 查 SQLite 写入权限（GuanXing 场景）。
- **缓解**：单模板异常已自动跳过（BD-03）；若全部目标不可达 → 检查网络 / 目标有效性。
- **升级**：排除上述仍 0 报告 → 回滚版本并提 issue。

#### 6.2.5 RB-03：外部 API 大面积降级

- **症状**：E-xx 降级率 > 50%（AL-03），CVE 仅用本地 257。
- **诊断**：查 `SHODAN_API_KEY` / `FOFA_KEY` / `NVD_API_KEY` 是否过期（L3/L4）。
- **缓解**：自动降级为本地 257 CVE 库（BD-01）；单源失败跳过（BD-02）；必要时手动轮换 Key（§7.2.3）。
- **升级**：Key 轮换后仍大面积失败 → 检查用户出站网络 / E-xx 服务状态。

#### 6.2.6 RB-04：单目标高失败率

- **症状**：单目标失败率 > 30%（AL-04）。
- **诊断**：查失败目标是否普遍不可达 / 被 WAF 拦截（per_domain_qps 限流）。
- **缓解**：遵守 `per_domain_qps=3.0` / `global_qps=10.0` 限速（§3.5.3）；降低 `scan.concurrency`。
- **升级**：持续高失败 → 检查目标有效性 / 网络。

#### 6.2.7 RB-05：磁盘水位 > 80%

- **症状**：磁盘已用 > 80%（AL-05，§8.1.4）。
- **诊断**：查 `scan_results/` 报告体积 / `guanxing.db` 大小。
- **缓解**：清理旧报告 / 归档；SQLite scans > 1GB 清理旧记录（§4.3.2）。
- **升级**：清理无效 → 扩容用户本机磁盘（用户侧）。

#### 7.2.2 密钥分级（security 权威，5 类）

| 分级 | 类型 | 存储 / 保护 | 访问控制 | 轮转周期 |
| --- | --- | --- | --- | --- |
| ① 数据库密码 | SQLite 无独立密码 | 以 `chmod 600` 文件权限替代（guanxing.db） | 仅本进程读取 | 文件权限随部署保障，无口令轮转 |
| ② 云 AK/SK 等价（E-xx API Key） | NVD/SHODAN/FOFA/CENSYS/GITHUB 等 | AES-256-GCM 加密 config / 环境变量 | 按源隔离签发，最小权限 | 泄露即禁用并轮换；各 E-xx 平台限额 / 白名单约束 |
| ③ 服务间密钥 | 不适用 | 无跨网络服务调用，无服务间密钥 | 不适用 | 不适用 |
| ④ 用户密码 | GuanXing Web 登录密码 | bcrypt / argon2 加盐哈希 | 本地账号，auth 开启时校验 | 用户手动修改 |
| ⑤ API Key / Token | 外部情报源令牌 | AES-256-GCM 加密 config / 环境变量 | 分级授权 / 可撤销 / 有限期 | 泄露即禁用并轮换；按源最小权限 |

#### 7.2.3 访问控制与轮转红线（security 权威）

- **访问控制**：本地无 CAM → 按源隔离最小权限 + 各 E-xx 平台限额 / 白名单；Key 分级授权、可撤销、有限期。
- **轮转策略**：Key 泄露即禁用并轮换；轮换 = 用户手动（系统设计 §7.2.3）；上线前 SCA + gitleaks 密钥扫描（§4.2 阶段 3 / §7.1.7）。
- **红线（严禁）**：硬编码密钥入代码 / 入 git；密钥入日志；密钥拼接入 URL；多业务共用同一 Key。违反即阻断发布（§4.5.4 发布门禁）。

### 7.3 访问审计接入
